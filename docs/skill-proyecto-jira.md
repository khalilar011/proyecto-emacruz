# Crear y usar la skill de proyecto integrador y Jira

La skill del equipo está en [`skills/alerta-ruta-jira/SKILL.md`](../skills/alerta-ruta-jira/SKILL.md). Su objetivo es revisar historias y entregas de Alerta Ruta con la misma pauta antes de cerrar una historia o enviar cambios. La conexión con Jira aporta las historias vigentes; la skill aporta el procedimiento de revisión.

1. **Define el alcance.** Mantén una sola responsabilidad: claridad de historias, criterios medibles, correspondencia con archivos y dictamen previo al push. Conserva `AGENTS.md` como reglas generales del repositorio.
2. **Revisa la estructura.** Una skill necesita una carpeta y un `SKILL.md` con `name` y `description` en el encabezado YAML. El archivo incluido ya contiene esa estructura. Modifica sus pasos cuando cambie el proceso del equipo; no incluyas credenciales ni datos institucionales.
3. **Hazla detectable por Codex.** Este repositorio ignora `.agents/`, así que la copia versionada vive en `skills/`. Desde la raíz del repositorio, crea un enlace local con `mkdir -p "$HOME/.agents/skills"` y `ln -s "$PWD/skills/alerta-ruta-jira" "$HOME/.agents/skills/alerta-ruta-jira"`. Si ya existe ese destino, revísalo antes de reemplazarlo. Otra opción de equipo es dejar de ignorar `.agents/skills/` y versionar la skill allí. Si Codex no la detecta, reinícialo. Hasta instalarla, pide que lea `skills/alerta-ruta-jira/SKILL.md` explícitamente.
4. **Conecta Jira y prueba una historia real.** Da a Codex una clave de Jira y acceso de lectura. Pide: «Usa $alerta-ruta-jira para revisar la historia CLAVE, su redacción, todos los criterios y su correspondencia con los archivos del repositorio. Devuelve la matriz y los bloqueos; no cambies Jira». Verifica que identifica criterios vagos y no atribuye decisiones pendientes a EMACRUZ.
5. **Prueba el cierre.** Con una rama preparada, pide la revisión del diff exacto antes del push. Comprueba que cada criterio tenga evidencia y que el resultado sea `BLOQUEADO` ante criterios sin prueba, archivos ajenos al alcance o datos no autorizados. Después de corregir, repite la revisión. Conserva el dictamen junto a la historia o solicitud de cambios.
6. **Automatiza el bloqueo si el equipo lo necesita.** La skill produce un dictamen para Codex, pero no impide por sí misma que alguien ejecute `git push`. Para un control técnico del equipo, configura en GitHub una rama protegida y una comprobación obligatoria que valide la evidencia acordada; define quién puede autorizar producción.

Para validar la estructura local de la skill, si está disponible la herramienta `skill-creator`, ejecuta su `scripts/quick_validate.py` con la ruta `skills/alerta-ruta-jira`. Esa comprobación valida el formato; la prueba con una historia real valida el comportamiento.
